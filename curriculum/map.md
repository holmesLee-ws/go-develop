# 커리큘럼 지도

큰 윤곽만 둔다. 강의 내용은 여기 없다. 튜터가 세션마다 학습자의 수준·목표에 맞춰 조사하고 만든다.

- 기본 순서는 F → C → S → X다. 선수 관계만 지키면 학습자의 목표에 맞춰 순서를 바꿔도 된다.
- 목표 수준은 그 모듈을 마쳤다고 볼 최소 수준이다. 수준의 뜻은 [tutor/assessment.md](../tutor/assessment.md)에 있다.
- 모듈 id는 진도 기록의 키다. 바꾸면 `learner/state.json`이 깨지므로, 고칠 때는 새 id를 만든다.
- `node tools/check.mjs`로 형식과 선수 관계를 검사한다(리포 관리자용, 학습자에게는 필요 없다).

## F · 기초 개발

### F1 · 터미널과 파일 시스템
- 선수: 없음
- 핵심 질문: 명령 한 줄을 치면 컴퓨터에서 무슨 일이 일어나는가?
- 목표: Apply — 경로·파이프·환경 변수로 파일을 찾고 가공한다.
- 만들어 볼 것: 로그 파일에서 오류 줄만 골라 세는 한 줄 명령
- 근거: CS2023 SDF·OS

### F2 · Git과 버전 관리
- 선수: F1
- 핵심 질문: Git은 변경 이력을 실제로 어떤 구조로 저장하는가?
- 목표: Apply — 브랜치를 나누고 합치고, 꼬인 이력을 되돌린다.
- 만들어 볼 것: 일부러 만든 병합 충돌을 풀고 되돌려 보기
- 근거: SWEBOK Software Configuration Management

### F3 · 프로그래밍의 뼈대
- 선수: F1
- 핵심 질문: 프로그램은 값과 흐름을 어떻게 다루는가?
- 목표: Apply — 변수·조건·반복·함수로 작은 문제를 푼다.
- 만들어 볼 것: 학습자가 고른 일상 문제를 푸는 작은 명령행 프로그램

### F4 · 데이터를 모양 짓기

- 핵심 질문: 같은 정보를 어떤 모양으로 담아야 다루기 쉬운가?

### F5 · 코드 읽기와 디버깅

- 만들어 볼 것: 버그가 심어진 프로그램의 원인 추적 기록
- 근거: CS2023 SDF, SWEBOK Software Construction

### F6 · 테스트 첫걸음
- 선수: F5
- 핵심 질문: 코드가 맞다는 것을 무엇으로 보장하는가?

### F7 · 웹과 HTTP
- 선수: F4
- 핵심 질문: 주소창에 URL을 치면 어떤 대화가 오가는가?

- 만들어 볼 것: JSON을 돌려주는 작은 HTTP 서버

### F8 · SQL과 데이터 저장
- 선수: F4
- 핵심 질문: 데이터를 파일이 아니라 데이터베이스에 두는 이유는 무엇인가?
- 목표: Apply — 테이블을 설계하고 조인·집계 쿼리를 쓴다.

## C · 컴퓨터 과학

### C1 · 데이터의 표현
- 선수: F3
- 핵심 질문: 0과 1로 숫자·글자·이미지를 어떻게 나타내는가?
- 목표: Explain — 정수 오버플로, 부동소수 오차, 문자 인코딩 깨짐의 원인을 설명한다.
- 만들어 볼 것: 0.1 + 0.2가 왜 0.3이 아닌지 비트로 추적하기
- 근거: CS2023 AR·SF

### C2 · 컴퓨터 구조
- 선수: C1
- 핵심 질문: CPU는 명령을 어떻게 실행하고, 메모리 계층은 왜 있는가?
- 목표: Explain — 캐시 지역성이 실행 시간에 주는 영향을 설명한다.
- 만들어 볼 것: 배열 순회 순서를 바꿔 실행 시간 차이 재기
- 근거: CS2023 AR·SF

### C3 · 운영체제
- 선수: C2, F1
- 핵심 질문: 프로그램 여러 개가 한 컴퓨터를 어떻게 나눠 쓰는가?
- 목표: Apply — 프로세스·가상 메모리·파일 디스크립터를 관찰하고 해석한다.
- 만들어 볼 것: 실행 중인 내 프로그램의 프로세스·메모리 관찰 기록
- 근거: CS2023 OS

### C4 · 네트워크
- 선수: F7, C3
- 핵심 질문: 패킷은 어떻게 지구 반대편까지 찾아가고, 믿을 수 없는 망에서 신뢰를 어떻게 얻는가?
- 목표: Apply — DNS·TCP·TLS 단계를 실제 도구로 추적한다.
- 만들어 볼 것: 내 요청 하나를 DNS부터 TLS까지 단계별로 추적하기
- 근거: CS2023 NC

### C5 · 자료구조
- 선수: F4
- 핵심 질문: 어떤 연산을 빠르게 하고 싶은가에 따라 구조는 어떻게 달라지는가?
- 목표: Evaluate — 연산 비용을 어림해 해시·트리·힙·그래프 중 문제에 맞는 구조를 근거와 함께 고른다.
- 만들어 볼 것: 해시 테이블을 직접 구현하고 충돌 다루기
- 근거: CS2023 AL

### C6 · 알고리즘과 복잡도
- 선수: C5
- 핵심 질문: 입력이 커지면 무엇이 먼저 무너지는가?
- 목표: Apply — 복잡도를 어림하고 탐색·정렬·재귀·동적 계획법을 적용한다.
- 만들어 볼 것: 느린 코드를 측정해 복잡도를 낮추기
- 근거: CS2023 AL

### C7 · 동시성과 병렬성
- 선수: C3

### C8 · 데이터베이스 내부

- 핵심 질문: 인덱스와 트랜잭션은 무엇을 약속하고 무엇을 대가로 치르는가?
- 목표: Evaluate — 실행 계획을 읽고 격리 수준의 영향을 판단한다.

### C9 · 프로그래밍 언어의 원리

- 만들어 볼 것: 아주 작은 계산기 언어의 파서와 실행기

### C10 · 수학적 사고와 계산의 한계
- 선수: C6
- 핵심 질문: 코드로 풀 수 없거나 사실상 풀기 어려운 문제는 왜 존재하는가?
- 목표: Explain — 논리·확률로 추론하고 P/NP·결정 불가능의 뜻을 설명한다.

## S · 소프트웨어 공학

- 선수: F3
- 핵심 질문: 사람들이 원한다고 말한 것과 실제로 필요한 것을 어떻게 가르는가?
- 목표: Apply — 모호한 요청을 검증 가능한 요구사항으로 바꾼다.
- 만들어 볼 것: 실제 불편 하나를 받아 합격 기준까지 쓰기

### S2 · 설계 원칙
- 선수: F6
- 핵심 질문: 변경하기 쉬운 코드는 무엇이 다른가?
- 목표: Evaluate — 결합도·응집도·추상화 관점으로 두 설계를 비교한다.
- 만들어 볼 것: 얽힌 코드를 나누고 변경 비용 비교하기

### S3 · 아키텍처와 트레이드오프

- 핵심 질문: 시스템의 큰 구조는 어떤 품질을 얻고 어떤 품질을 포기하는 선택인가?
- 목표: Evaluate — 모놀리스·서비스 분리·큐·캐시를 제약에 맞춰 고른다.

### S4 · API와 계약

- 만들어 볼 것: F7 서버의 API를 호환을 지키며 개정하기
- 근거: SWEBOK Software Design, CS2023 SE

### S5 · 구현 품질과 유지보수

### S6 · 테스트 전략

## 이 지도에 넣지 않은 영역

CS2023의 Artificial Intelligence, Graphics and Interactive Techniques, Human-Computer Interaction, Specialized Platform Development는 깊게 다루지 않는다. 학습자가 원하면 튜터가 선택 모듈로 더한다. 선택 모듈 id는 `E`로 시작하고 `learner/state.json`에만 둔다.
